# The expected-fail list — the executable half of wasi/COMPATIBILITY.md.
#
#   <suite>/<test>   <class>   <reason>
#
# Class is what COMPATIBILITY.md marks the row, and the three exist so that a
# defect is never quietly filed as a divergence:
#
#   divergence  the browser does not have the feature. A blank cell. Permanent
#               until the platform changes, and NOT a thing to fix.
#   gesture     real in a browser, but gated behind a user gesture no automated
#               test can supply. A game can reach it from a click; this cannot.
#   defect      the browser has it and we do not. Names its issue. THIS IS THE
#               TO-DO LIST, and it should only ever get shorter.
#
# wasi/corpus/run.sh fails if a test here PASSES: an unearned divergence is a
# lie, and a fixed defect must be struck from the list in the same change that
# fixes it. It also fails on a name here that the corpus does not have, so a
# renamed or deleted upstream test cannot hide a real failure behind a dead line.

# The four rasterisation near-misses are GONE from this list as of #54.
# They were never real failures: upstream's harness has the tolerance knobs
# (rgba_tolerance, pixel_tolerance) and grants them for exactly this class of
# difference, but every gate was keyed to a platform that is not "Web". Each
# differing shape pixel matched a neighbouring reference pixel EXACTLY (a
# fill-rule tie-break in the rasteriser) and the setLineStyle delta was 3/255
# in one channel of an antialiased blend. testing/tests/graphics.lua now gates
# on isOS('Web') for arc, circle, ellipse and setLineStyle, and they pass.
#
# Note for anyone adding a Web gate later: do NOT copy upstream's
# `GITHUB_RUNNER and test:isOS(...)` form. GITHUB_RUNNER comes from the
# --isRunner argument, and a wasm host has no argv to pass it, so a
# runner-gated branch never runs here — it would look like a fix and change
# nothing.
#
# graphics/arc did NOT join them, and is the first entry on the defect list.
# Tolerating its boundary tie-break advanced compareImg's scan past the pixel it
# had been stopping on, and a real fault was underneath: at (2,7) we render pure
# white where the reference and all eight of its neighbours are yellow — a blue
# delta of 255/255, the maximum possible. Two problems were stacked on one test
# and only the first was ever visible. See #71.
graphics/arc	defect	#71 — 'fill' + "open" arc does not cover (2,7); the line arc underneath shows through. Measured: b=1.0 vs 0.0, 255/255
